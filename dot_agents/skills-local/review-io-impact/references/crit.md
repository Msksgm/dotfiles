# crit でブラウザ表示する

レポートをブラウザで読みたいときは `crit` に渡す。全モードで有効。

### 発火条件

ユーザーが「crit で見たい」「ブラウザで」「html で」等と言ったとき、または引数に `--crit` があるとき**だけ**実行する。**既定では会話に出すだけでファイルは書かない。**

### 手順

1. 対象モードのレポートを作成し、Markdown に書き出す。図は [impact-diagram](../../impact-diagram/SKILL.md) に出力形式 Mermaid を指定して、**初回から Mermaid で組み立てる**。既存の会話レポートを使う場合も、ASCII 図は Mermaid に置き換える。
   - 出力先: `${TMPDIR:-/tmp}/review-io-impact-<slug>.md`
   - `<slug>` は対象（PR 番号 / ブランチ名 / 機能名）から作る
   - **リポジトリ内には書かない**。レビュー成果物を git に混入させないため
   - **本文の前に「要約」と「目次」を置く**（crit MD 限定。会話出力には付けない）。書式は §crit MD の先頭構造 に従う
2. `crit <絶対パス>` を **会話をブロックしない方法で起動する**（`run_in_background: true`、または実行ツールが返す継続可能なセッションを使用する）
   - crit は「Finish Review」がクリックされるまでブロックするため、**フォアグラウンドで実行してはいけない**（会話が止まる）
3. 起動ログの `Started crit daemon at http://localhost:<port>` を拾い、URL をユーザーに報告する
4. ユーザーがブラウザ上でコメントを残したら `crit comments --json` で回収して対応する。このラウンドは**何度も繰り返される**前提で扱う（crit プラグインの `crit-cli` skill が利用可能なら、コメント操作の詳細はそちらを参照する）
   - 図の追加・修正は `impact-diagram`、本文・要約・目次と crit 操作は呼び出し元の `review-io-impact` が担当する。
   - コメント対応で crit md を追記・修正するときも、**新規に描く図は最初から Mermaid で書く**。ASCII で書いてから直す、はしない
   - 節を追記・削除・改名したら、**同じ編集で要約と目次も更新する**（§crit MD の先頭構造）。後追いにしない

### crit MD の先頭構造

本文の各セクションは対象モードの [impact 書式](report-impact.md) または [explain / explore 書式](report-explain.md) のとおり（該当する片方だけ読む）。**その前に「要約」「目次」を置く**。

見出しレベルは会話出力から 1 段上げる — 対象モードの書式の `## review-io-impact 結果` とモード行はファイル冒頭の `#` タイトル ＋ 引用行が兼ねるので**重複して置かない**。本文セクション（`📋 変更サマリ` 等）は `##` にする。

```markdown
# review-io-impact: <対象（PR 番号 / ブランチ名 / 機能名）>

> モード: … ／ プロジェクト map: 使用 or 未使用

## 要約

- **変更**: 何をどう変えたか（1 行）
- **影響**: どの入口 → どの出口に、どんな条件で効くか（1〜2 行）
- **テスト**: 充足 / 不足（不足ならどの経路が守られていないか）
- **要確認**: レビュアーが自分で判断すべき論点があるか（無ければ「なし」）

## 目次

1. [📋 変更サマリ](#-変更サマリ)
2. [🔄 I/O](#-io)
3. [🚪 入口カタログ](#-入口カタログ)
   …（本文セクションを出現順に。下位見出しは必要な場合のみ 2 階層まで）

## 📋 変更サマリ
…
```

#### 要約のルール

- **結論を先に書く**。経路の辿り方や根拠は本文に譲る
- 4 項目・各 1〜2 行、**全体で 8 行以内**に収める。ここが長いと目次まで届かず先頭構造の意味が消える
- 断定と推測の区別は原則どおり守る。未確認のことは「要確認」に寄せ、断定形で書かない
- `impact` モードでも同じ 4 項目（モードによって項目を変えない）

#### 目次のルール

- **アンカーリンク形式**（`[📋 変更サマリ](#-変更サマリ)`）で書く
- アンカーは GitHub 方式で機械的に導出する: 見出しから絵文字・記号を除去 → 小文字化 → 空白を `-` に置換。絵文字見出しは先頭に `-` が残る（`## 📋 変更サマリ` → `#-変更サマリ`）
- **リンクテキストは本文の見出し文字列と一字一句一致させる**。レンダラがアンカーを解決しない場合でも見出し名で検索して辿れるようにするため（リンク切れの保険）
- 列挙は**本文の出現順**。本文セクション（`##`）を基本とし、その下位見出し（`###`）は情報量が多い節だけ 2 階層目まで
- 本文に無い節を目次に書かない / 本文にある節を落とさない

#### コメント対応ラウンドでの保守

- 節を追記・削除・改名したら、**要約と目次も同じ編集で更新する**
- 結論が変わる修正（テスト判定が充足→不足になる等）を入れたら、要約の該当項目を必ず書き換える

### 注意

- crit は**レビュー UI** であり、行番号ガーターとコメント欄が常に付く。読み取り専用の閲覧モードは無い
- **静的 HTML ファイルは生成されない**。crit はローカルサーバを立ててクライアント側で描画する（`crit export` や `--html` は存在しない）。オフラインで配れる成果物が要る場合は `crit share` を使うが、これは外部サービス（`crit.md`）への**アップロード＝ネットワーク送信**を伴うので、**ユーザーの明示指示なしに実行しない**
- `open ~/.crit/sessions/<id>.lock: operation not permitted` (EPERM) で起動に失敗する場合は、`~/.crit` がサンドボックスの書き込み allowlist に入っているか確認する
