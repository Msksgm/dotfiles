# impact-diagram

確認済みの経路を、読み手が入口から出口まで追える図にする。`review-io-impact` の結果だけでなく、ユーザーが渡した既存レポートや会話内の経路情報からも単独で利用できる。

## 入力と責務

入力は既存の表・箇条書き・レポートでよい。専用JSONや中間ファイルを要求しない。

- 入口、変更箇所、出口と、それらを結ぶ経路
- 分岐・影響条件、合流点、影響しない経路
- 同一プロセスの呼び出し、RPC、enqueue・workerなどの非同期境界
- 根拠（`path:line` など）、未確認事項、対象の名称、希望する出力形式

図に必要な情報が揃っていれば再調査しない。情報が不足する部分は「未確認」として明示し、接続・合流・影響の有無を推測で追加しない。図の分割を理由に影響条件や根拠を落とさない。

追加調査が必要なら不足する経路を具体的に示す。呼び出し元が `review-io-impact` ならそちらで調査を補う。単独利用では確認済みの範囲を描き、必要な追加情報を伝える。描画だけの依頼から影響調査やテスト判定へ自動的に広げない。

## 図への分割

1. **全体図**を基本とする。入口群 → 合流点（ある場合）→ 変更箇所 → 出口群を示し、変更箇所と合流点をラベルや枠で強調する。合流しない経路は分けたまま描く。
2. 全体図で経路やラベルが混み合う場合は、**入口別図**をプロトコルごとに追加し、operation から変更箇所までを詳しく示す。
3. 出口への分岐が複雑な場合は、**出口図**を追加し、変更箇所から永続化・ファイル・レスポンス・イベントなどへの条件付きの波及を示す。

各詳細図の見出しに全体図のどの部分かを書く。同じノードは同じ名称または短い識別子で統一し、共通の接続点を各図に残す。RPC・非同期境界は矢印のラベル等で明示し、単純な同一プロセス呼び出しとして縮約しない。

分岐条件は対応する矢印か隣接する表に置く。根拠が多い場合は図のノード・経路と対応する根拠表にまとめる。影響しない経路は、影響する経路と区別できる枠・ラベルまたは別表で示す。色だけで区別しない。

図は既定で最大5枚。収まらない詳細は表で補う。ユーザーが経路ごとの図示を明示した場合は5枚を超えてよい。全体図だけで読める場合、入口別図・出口図を機械的に増やさない。

## 記法と出力

| 出力先 | 記法 |
|---|---|
| Codex appの会話 | 初回・追記・修正とも Mermaid |
| その他の会話（既定） | ASCII罫線 |
| 会話で記法を指定された場合 | 指定された記法 |
| crit向けレポート | 初回・追記・修正とも Mermaid |

ユーザーが記法を明示した場合はその指定を優先する。指定がなければ、実行環境や会話の文脈からCodex appと分かる場合は、単独利用・他skill経由のどちらでもMermaidを使う。環境が不明ならその他の会話の既定に従う。

Codex appとcrit向けは最初から `mermaid` コードブロックで作る。ノードIDと表示ラベルを分け、記号を含むラベルは引用符で囲む。未確認の経路を描く場合は、確定した接続と区別して「未確認」と明記する。

### 変更箇所の色分け

Mermaidでは、実際に変更されたノードを背景色と枠線で強調し、ラベルにも「変更」を付ける。全体図・詳細図で同じ色を使い、図の近くに「オレンジ色＝変更箇所」の凡例を添える。単に影響を受ける出口や未変更の合流点には変更色を付けない。変更箇所が未確認、または既存機能の説明で差分がない場合は、変更ノードを作らない。

次の定義を基本とし、該当するノードIDに `changed` を割り当てる。背景・文字・枠線をセットで指定し、明暗どちらのテーマでも文字を読めるようにする。

```mermaid
flowchart LR
    entry["入口"] --> changedNode["変更: 計算処理"] --> output["出力"]
    classDef changed fill:#FFEDD5,stroke:#C2410C,color:#431407,stroke-width:3px;
    class changedNode changed;
```

ASCII出力ではANSIカラーを埋め込まず、`[変更]` ラベルと枠で強調する。色を表示できる図では色とラベルを併用する。

成果物は図と、読むために必要な短い説明・条件表・根拠表。既定では会話に返す。呼び出し元がある場合は、指定形式の図をレポートに組み込める形で渡す。critの起動、コメント回収、レポート全体の要約・目次の管理は呼び出し元が担当する。

## 最終確認

- 入力の経路・条件と図を照合し、分割による接続の欠落や架空の合流がないか確認する。
- 図を跨いでも同じ要素を追え、RPC・非同期・影響しない経路を区別できるか確認する。
- 未確認事項と根拠を保持し、出力先に合った記法になっているか確認する。
- Mermaidの変更ノードに色と「変更」ラベルが付き、影響先と変更箇所を混同していないか確認する。
