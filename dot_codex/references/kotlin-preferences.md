# Kotlin 編集時の方針

Kotlin コードやテストを編集するときの個人設定。対象リポジトリの明示的な規約と整合させ、依頼された変更範囲に適用する。既存コード全体への一括適用はしない。

## デフォルト引数

- 呼び出し側が明示的に選ぶべき値に、呼び出し箇所の修正を省くためだけのデフォルト値を追加しない。
- 省略時の動作が仕様として意味を持つ場合は、デフォルト引数を使ってよい。
- nullable であることと、引数を省略可能にすることは別に判断する。`null` が「上書きなし」を表す場合でも、呼び出し側に明示させる設計を選べる。
- デフォルト値を削除するときは、本番コード・テスト・fixture の呼び出しを確認し、必要な値を明示する。

## import

- 型や enum は原則として通常の import を使い、使用箇所に完全修飾名を書かない。
- 名前が衝突する場合は import alias を検討する。区別のために完全修飾名が必要な場合は例外とする。

## データ駆動テスト

- データ駆動化の前に、各ケースが異なる振る舞いや境界条件を検証しているか確認する。同じ経路を繰り返すだけなら代表的な1ケースに絞る。
- 共通の検証を複数の入力で行う場合は、既存のデータ駆動テストの書式に揃える。`withIts` を採用しているリポジトリでは、意図が分かる名前付きケースを使う。
- 1ケースしか必要ない場合は通常の `it` などで書く。`withIts` を使うためにケースを増やさない。
- `withIts` が存在しないプロジェクトに、この方針だけを理由として独自ヘルパーや依存関係を追加しない。
- ケース間で変わる入力をデータにし、共通の準備・実行・検証はテスト本体に置く。期待値は実装と同じ計算で導出せず、具体値で示す。
